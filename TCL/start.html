1. ¿Qué es una transacción?

Una transacción es un conjunto de operaciones SQL que se ejecutan como una unidad.

Esto permite decidir al final si los cambios se guardan o si se deshacen. 

Transacción
    ↓
Varias operaciones SQL
    ↓
COMMIT
o
ROLLBACK

2. Sintaxis

Para comenzar una transacción utilizamos: 

START TRANSACTION;

A partir de ese momento, las operaciones que realizamos pueden ser confirmadas con COMMIT o deshechas con ROLLBACK. 

START TRANSACTION;

UPDATE ...;

INSERT ...;

DELETE ...;

COMMIT;

3. ¿Cómo funciona?

Al iniciar una transacción, los cambios quedan pendientes hasta que decidimos qué hacer con ellos.

1. Iniciar

START TRANSACTION;

Comienza la transacción.

2. Ejecutar cambios

UPDATE
INSERT
DELETE

Se realizan las operaciones.

3. Decidir

COMMIT

o

ROLLBACK

Confirmamos o deshacemos.

4. Confirmar con COMMIT

Si todo salió correctamente, utilizamos COMMIT para guardar definitivamente los cambios. 

START TRANSACTION;

UPDATE cuentas
SET saldo = saldo - 1000
WHERE id = 1;

UPDATE cuentas
SET saldo = saldo + 1000
WHERE id = 2;

COMMIT;

Después de ejecutar COMMIT, los cambios quedan confirmados. 

START TRANSACTION
      ↓
Cambios
      ↓
COMMIT
      ↓
GUARDAR

5. Deshacer con ROLLBACK

Si detectamos un problema, podemos utilizar ROLLBACK para cancelar los cambios realizados durante la transacción. 

START TRANSACTION;

UPDATE cuentas
SET saldo = saldo - 1000
WHERE id = 1;

UPDATE cuentas
SET saldo = saldo + 1000
WHERE id = 2;

ROLLBACK;

Los cambios realizados desde el inicio de la transacción se deshacen. 

START TRANSACTION
      ↓
Cambios
      ↓
ROLLBACK
      ↓
DESHACER

6. Ejemplo: transferencia bancaria

Imaginemos una transferencia de $1000 desde una cuenta hacia otra.

Primero debemos restar dinero de una cuenta: 

UPDATE cuentas
SET saldo = saldo - 1000
WHERE id = 1;

Luego debemos sumarlo a la segunda cuenta: 

UPDATE cuentas
SET saldo = saldo + 1000
WHERE id = 2;

Lo correcto sería ejecutar ambas operaciones dentro de una transacción: 

START TRANSACTION;

UPDATE cuentas
SET saldo = saldo - 1000
WHERE id = 1;

UPDATE cuentas
SET saldo = saldo + 1000
WHERE id = 2;

COMMIT;

De esta forma, las dos operaciones forman una sola unidad lógica.

Si todo sale bien

COMMIT;

Se guardan los cambios.

Si algo falla

ROLLBACK;

Se deshacen los cambios.

7. AUTOCOMMIT

En MySQL normalmente está activo el modo autocommit.

Esto significa que una instrucción se confirma automáticamente después de ejecutarse. 

UPDATE alumnos
SET nombre = 'Ana'
WHERE id = 1;

Si no estamos dentro de una transacción, el cambio puede quedar confirmado automáticamente.

Con: 

START TRANSACTION;

podemos controlar manualmente cuándo guardar o deshacer las operaciones.

8. Errores comunes

Olvidar COMMIT

Los cambios pueden quedar sin confirmar.

Olvidar ROLLBACK

Si algo falla, conviene deshacer las operaciones pendientes.

Usar operaciones aisladas

Algunas operaciones dependen unas de otras y deberían ejecutarse juntas.

Confundir con SAVEPOINT

SAVEPOINT permite marcar puntos intermedios dentro de una transacción.

9. ¿Cuándo conviene usar transacciones?

Son especialmente útiles cuando varias operaciones dependen entre sí.

🏦 Transferencias

Restar dinero de una cuenta y sumarlo en otra.

🛒 Compras

Crear una venta, registrar productos y descontar stock.

📚 Inscripciones

Registrar al alumno y asociarlo a un curso.

🎵 Reproductor

Crear una lista y agregarle varios temas.
