1. ¿Qué hace GRANT?

La instrucción GRANT permite otorgar permisos a un usuario sobre una base de datos, una tabla u otros objetos del gestor.

Forma parte de las instrucciones DCL, ya que se utiliza para controlar el acceso de los usuarios.

2. Sintaxis general

GRANT privilegio

ON base.tabla

TO 'usuario'@'host';

La instrucción tiene tres partes importantes:

Privilegio

Indica qué acción puede realizar el usuario. 

SELECT
INSERT
UPDATE
DELETE

Objeto

Indica sobre qué base o tabla se aplica el permiso. 

escuela.alumnos

Usuario

Indica quién recibe el permiso. 

'juan'@'localhost'

3. Otorgar permiso SELECT

El permiso SELECT permite consultar información. 

GRANT SELECT

ON escuela.alumnos

TO 'juan'@'localhost';

El usuario juan podrá consultar la tabla alumnos, pero no podrá modificar sus datos si no tiene otros permisos.

↑ Anterior | ↓ Siguiente

4. Otorgar varios permisos

Podemos otorgar más de un privilegio en una misma instrucción. 

GRANT SELECT, INSERT, UPDATE

ON escuela.alumnos

TO 'juan'@'localhost';

En este caso el usuario puede:

SELECT

Consultar registros.

INSERT

Agregar registros.

UPDATE

Modificar registros.

5. Permisos sobre una tabla

Podemos dar permisos solamente sobre una tabla específica. 

GRANT SELECT

ON escuela.alumnos

TO 'juan'@'localhost';

El usuario puede consultar escuela.alumnos, pero eso no significa que tenga acceso a todas las demás tablas de la base.

↑ Anterior | ↓ Siguiente

6. Permisos sobre toda una base de datos

El símbolo * representa todas las tablas de una base de datos. 

GRANT SELECT

ON escuela.*

TO 'juan'@'localhost';

El usuario podrá realizar consultas sobre todas las tablas de la base escuela. 

escuela.*
        ↓

7. ALL PRIVILEGES

ALL PRIVILEGES permite otorgar todos los privilegios disponibles para el nivel indicado. 

GRANT ALL PRIVILEGES

ON escuela.*

TO 'admin'@'localhost';

En este caso admin recibe todos los privilegios sobre la base escuela.

Atención: no conviene otorgar más permisos de los necesarios.

8. Usuario y host

En MySQL y MariaDB, un usuario se identifica por su nombre y por el lugar desde donde puede conectarse. 

'juan'@'localhost'

Esto significa:

'juan'

Nombre del usuario.

'localhost'

Puede conectarse desde el mismo servidor.

Por ejemplo: 

GRANT SELECT

ON escuela.*

TO 'juan'@'localhost';

Privilegios comunes

SELECT

Consultar información.

INSERT

Agregar registros.

UPDATE

Modificar registros.

DELETE

Eliminar registros.

CREATE

Crear objetos.

DROP

Eliminar objetos.

ALTER

Modificar estructuras.

Ejemplos de permisos

Solo lectura: 

GRANT SELECT

ON escuela.*

TO 'lector'@'localhost';

Lectura y escritura: 

GRANT SELECT, INSERT, UPDATE, DELETE

ON escuela.*

TO 'editor'@'localhost';

Permisos completos: 

GRANT ALL PRIVILEGES

ON escuela.*

TO 'administrador'@'localhost';

9. Errores comunes

Usuario incorrecto

El usuario indicado puede no existir.

Host incorrecto

El usuario puede existir para otro host.

Objeto incorrecto

La base o tabla indicada puede no existir.

Exceso de permisos

Dar ALL PRIVILEGES cuando no es necesario.

Buena práctica

Lo recomendable es otorgar solamente los permisos que el usuario realmente necesita.

Por ejemplo, si un usuario solamente necesita consultar: 

GRANT SELECT

ON escuela.*

TO 'lector'@'localhost';

No sería necesario darle: 

INSERT
UPDATE
DELETE
DROP
