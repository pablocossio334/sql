1. ¿Qué hace REVOKE?

La instrucción REVOKE permite quitar permisos que habían sido otorgados previamente a un usuario.

Forma parte de las instrucciones DCL, porque controla los privilegios y accesos de los usuarios.

2. Sintaxis general

REVOKE privilegio

ON base.tabla

FROM 'usuario'@'host';

La diferencia principal con GRANT es que usamos FROM en lugar de TO.

3. Quitar permiso SELECT

Podemos quitar el permiso de lectura sobre una tabla. 

REVOKE SELECT

ON escuela.alumnos

FROM 'juan'@'localhost';

Después de esto, el usuario juan ya no podrá consultar esa tabla mediante SELECT.

↑ Anterior | ↓ Siguiente

4. Quitar varios permisos

Podemos quitar varios privilegios en una sola instrucción. 

REVOKE SELECT, INSERT, UPDATE

ON escuela.alumnos

FROM 'juan'@'localhost';

El usuario perderá esos tres permisos sobre la tabla.

SELECT

Ya no podrá consultar.

INSERT

Ya no podrá agregar registros.

UPDATE

Ya no podrá modificar registros.

↑ Anterior | ↓ Siguiente

5. Quitar permisos sobre una tabla

Podemos quitar un privilegio solamente sobre una tabla específica. 

REVOKE DELETE

ON escuela.alumnos

FROM 'juan'@'localhost';

Esto no afecta necesariamente los permisos que el usuario tenga sobre otras tablas.

↑ Anterior | ↓ Siguiente

6. Quitar permisos sobre una base de datos

Utilizando * podemos aplicar REVOKE sobre todas las tablas de una base de datos. 

REVOKE SELECT

ON escuela.*

FROM 'juan'@'localhost';

El usuario perderá el permiso SELECT sobre todas las tablas de escuela. 

escuela.*
      ↓
Todas las tablas

7. Quitar ALL PRIVILEGES

Podemos quitar todos los privilegios que un usuario tenga sobre un determinado nivel. 

REVOKE ALL PRIVILEGES

ON escuela.*

FROM 'admin'@'localhost';

Esto elimina los privilegios sobre la base de datos escuela para ese usuario.

Importante: esto no significa necesariamente que el usuario deje de existir.

Se están quitando privilegios, no eliminando la cuenta.

8. GRANT vs REVOKE

GRANT

Otorga permisos. 

GRANT SELECT
ON escuela.*
TO 'juan'@'localhost';

REVOKE

Quita permisos. 

REVOKE SELECT
ON escuela.*
FROM 'juan'@'localhost';

Una diferencia fácil de recordar: 

GRANT ... TO usuario
        ↓
DAR


REVOKE ... FROM usuario
        ↓
QUITAR

↑ Anterior | ↓ Siguiente

Ejemplo paso a paso

Primero otorgamos permisos: 

GRANT SELECT, INSERT, UPDATE

ON escuela.alumnos

TO 'juan'@'localhost';

El usuario puede: 

SELECT
INSERT
UPDATE

Después decidimos quitar UPDATE: 

REVOKE UPDATE

ON escuela.alumnos

FROM 'juan'@'localhost';

Ahora conserva: 

SELECT
INSERT

pero ya no posee: 

UPDATE

REVOKE no elimina al usuario

Es importante diferenciar entre quitar permisos y eliminar una cuenta. 

REVOKE
     ↓
Quita permisos


DROP USER
     ↓
Elimina usuario

Por ejemplo: 

REVOKE SELECT

ON escuela.*

FROM 'juan'@'localhost';

El usuario sigue existiendo, pero perdió ese privilegio.

9. Errores comunes

Usuario incorrecto

Es importante indicar correctamente usuario y host.

Objeto incorrecto

La base o tabla indicada puede ser incorrecta.

Privilegio incorrecto

Debemos indicar exactamente qué permiso queremos quitar.

Confundir con DROP USER

REVOKE quita permisos, no elimina usuarios.

↑ Anterior | ↓ Siguiente

Buena práctica

Si un usuario deja de necesitar determinado acceso, podemos quitar solamente ese privilegio.

Por ejemplo: 

REVOKE DELETE

ON escuela.*

FROM 'editor'@'localhost';

El usuario puede conservar otros privilegios como: 

SELECT
INSERT
UPDATE

pero ya no podrá eliminar registros.
